You're right — that's exactly what SITEID=ALL does, and the CSV you just sent proves why you need it.

What the 19010 CSV shows

Every row is PITTSBURGH PA P&DC — 80+ machines across AFCS200, AFSM100, ATU, DBCS, DIOSS, PSS, SSM, Manual Parcels, etc. Zero rows from 19006 Monroeville, 19011 Greentree, 19008 Penn Hills, 19007 Woods Run, 19009 Washington, 19401 Pleasant Hills S&DC — all of which are in the same site dropdown we saw in the debug HTML. Picking a specific parent site in the mapping UI returns only that site's machines, despite the CONNECT BY PRIOR hierarchy being computed in the SQL (the final AND machine.site_id = 19010 collapses it back to the parent).

That's why you want SITEID=ALL. That value drops the per-site filter entirely, and the returned rows are whatever the logged-in account's scope allows — parent plant plus every branch, listed by SITE_NAME as the CSV's primary sort.

Wiring it up

The function I gave last message already accepts "ALL" as $SiteId, but the UI can't pick it yet — Get-WebEorSiteList filters on value="(\d+)" so the <OPTION VALUE="ALL">ALL</OPTION> entry gets dropped from the ComboBox.

The cleanest fix: keep the dropdown for EOR (which requires a numeric site), and add an explicit mapping-scope selector next to the mapping checkbox.

1. Add a mapping-scope selector

In the dialog, find the existing mapping checkbox:

```powershell
$chkMapping = New-Object System.Windows.Forms.CheckBox
$chkMapping.Text = "Also fetch machine mapping CSV (unverified)"
$chkMapping.Location = New-Object System.Drawing.Point(70, 160)
$chkMapping.Size = New-Object System.Drawing.Size(340, 22)
```

Replace with:

```powershell
$chkMapping = New-Object System.Windows.Forms.CheckBox
$chkMapping.Text = "Also fetch machine mapping CSV"
$chkMapping.Location = New-Object System.Drawing.Point(70, 160)
$chkMapping.Size = New-Object System.Drawing.Size(260, 22)
$chkMapping.Checked = $false
$dlg.Controls.Add($chkMapping)

# Mapping scope: which SITEID the mapping request uses
$lblScope = New-Object System.Windows.Forms.Label
$lblScope.Text = "scope:"
$lblScope.Location = New-Object System.Drawing.Point(335, 160)
$lblScope.Size = New-Object System.Drawing.Size(45, 22)
$lblScope.TextAlign = 'MiddleLeft'
$dlg.Controls.Add($lblScope)

$cmbMapScope = New-Object System.Windows.Forms.ComboBox
$cmbMapScope.Location = New-Object System.Drawing.Point(380, 158)
$cmbMapScope.Size = New-Object System.Drawing.Size(300, 24)
$cmbMapScope.DropDownStyle = 'DropDownList'
[void]$cmbMapScope.Items.Add("This site only")
[void]$cmbMapScope.Items.Add("ALL sites (parent + children)")
$cmbMapScope.SelectedIndex = 1   # default to ALL — that's what you actually want
$dlg.Controls.Add($cmbMapScope)
```

2. Update the download button handler

Find where mapping is fetched:

```powershell
if ($chkMapping.Checked) {
    $mapFile = Join-Path $outDir ("MachineMapping_{0}.csv" -f $sid)
    $lblStatus.Text = "Fetching machine mapping..."
    try {
        $null = Save-MachineMappingCsv -Session $script:Session `
            -SiteId $sid -OutFile $mapFile
    } catch {
        Write-DlLog "Mapping download failed (EOR still saved): $($_.Exception.Message)" -Level Error
    }
}
```

Replace with:

```powershell
if ($chkMapping.Checked) {
    # Scope: "ALL" gives parent + children; the numeric site gives just that site
    $mapScope = if ($cmbMapScope.SelectedIndex -eq 1) { "ALL" } else { [string]$sid }
    $mapFile  = Join-Path $outDir ("MachineMapping_{0}.csv" -f $mapScope)
    $scopeLabel = if ($mapScope -eq "ALL") { "ALL sites in scope (parent + children)" }
                  else { "site $mapScope only" }

    Write-DlLog "Fetching machine mapping — $scopeLabel" -Level Info
    $lblStatus.Text = "Fetching machine mapping ($mapScope)..."
    [System.Windows.Forms.Application]::DoEvents()

    try {
        $m = Save-MachineMappingCsv -Session $script:Session `
            -SiteId $mapScope -MachineType "ALL" -Status "Y" -OutFile $mapFile
        Write-DlLog "Machine mapping saved: $($m.FullName) ($([math]::Round($m.Length/1KB,1)) KB)" -Level Success
    } catch {
        Write-DlLog "Mapping download failed (EOR still saved): $($_.Exception.Message)" -Level Error
    }
}
```

3. Persist the scope choice (optional, nice to have)

Add to Load-Settings defaults:

```powershell
MappingScope = 1      # 0 = this site only, 1 = ALL sites
```

And in the settings-save block of the download handler:

```powershell
$settings.MappingScope = $cmbMapScope.SelectedIndex
```

And after the ComboBox is created:

```powershell
if ($settings.MappingScope -ne $null) {
    $cmbMapScope.SelectedIndex = [int]$settings.MappingScope
}
```

Two things from the 19010 CSV worth confirming

Both are normal, nothing to fix:

· Blank Global ID for Manual Parcels / Manual Letter Case / etc. — those aren't machine-backed, they're operations. The SQL returns global_machine_id = NULL and the CSV renders it as an empty field between commas. Expected.
· Trailing source text (as plain string, not <a href>) for AFCS/AFSM/PSM/SSM rows, blank for F/C and Manual types — the CSV endpoint is stripping the <a href="javascript:...">source</a> wrapper the SQL builds in source_link and just returning the anchor text. Cleaner than what the browser would give you, and it means the strip step I considered last message would have been redundant. Leave it alone.
